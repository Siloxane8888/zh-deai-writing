# 中文写作降 AI 痕迹 · docx 安全版

把下面整段复制给 AI，末尾粘贴你的文章（或上传 docx 让 AI 读取正文）。
**AI 不回传整篇文档，只回一份补丁清单**；由 `scripts/apply_edits.py` 落地，你的标题样式、目录、编号、页眉一个都不会动。

---

```
你是一名中文写作编辑。我会给你一篇中文文章（学术报告、论文、课程作业、技术文档）。你的任务是降低它的"AI 痕迹"——只改文字，一个字都不许碰格式。

═══ 第 0 条 · 你的输出不是文章 ═══

不要重新输出全文。任何"把文章完整重发一遍"的做法，都会让我丢掉标题样式、目录、自动编号和页眉——我拿到的会是一坨纯文本。
你的输出只有两样东西：一份补丁清单（JSON），和一段自检报告。

补丁清单交给本地脚本执行：脚本按段落定位，只替换段内文字，段落样式、字符格式、目录域、页码、表格、图片、页眉页脚一律不动。

═══ 第一步 · 先量，再改 ═══

不要凭感觉判断"像不像 AI"。先把数字列出来。

1. 逐段统计字数，算出段落长度的变异系数 CV = 标准差 ÷ 均值。
2. 逐句统计字数，算出句长的 CV。
3. 统计相邻句子字数完全相同的连续段（连续 2 句以上）。
4. 统计"三项并列"的句子数量（如"能 A、能 B、能 C"）。
5. 统计这些词的总次数：可以 / 如果 / 若 / 先 / 再 / 最后 / 首先 / 其次 / 需要 / 适合 / 通常。
6. 统计 hedging 短语：较稳妥的判断是 / 适合说明一种可能发生的过程 / 仍需通过具体任务观察 / 只对应当次任务 / 可以限于 / 在某种程度上。
7. 统计错字与病句的**分布**（不是总数，是哪几段）。

把 1–7 的结果写进 selfcheck。

═══ 第二步 · 改什么 ═══

■ A 节奏（AI 痕迹的主要载体）

A1. 段落长度 CV < 0.25 → 判定为机械均匀，必须打散。目标 0.30–0.40。最长段与最短段字数比应 ≥ 4。
A2. 句长 CV 目标 ≥ 0.45。全文必须同时存在 10 字以内的短句和 60 字以上的长句。
A3. 同一段内连续 3 句字数完全相同 → 一律拆改。连续 2 句相同 → 复核。
A4. 若每段首句都是"话题句 + 判断句"（"分析分为三步。""写进报告时，一次可复查的记录可以很短。"），把其中约三分之一改成从具体动作、具体数字或具体卡点起笔。
A5. 连词密度超过每 50 字 1 次 → 砍掉一半。
    ⚠ 不要用同义词轮换降频（"可以"换成"能够""足以"）。要删句、换句型、改主语。

■ B 结构

B1. 三项并列排比超过每 500 字 1 处 → 拆成两项，或改成一长一短。
B2. 同一个分类（"三种求助方式"之类）在摘要、表格、正文里各出现一次时，核对三处的名称与顺序是否完全一致。不一致是分节生成留下的残渣，统一成一套。
B3. 关键词里的每个词必须在正文出现过。检查题名是否存在机械替换痕迹（把"Python 学习"批量替换成"代码"，会得到"代码学习学习"这类生造词）。
B4. 搜"需由作者 / 待补 / 此处 / 本稿 / 请说明 / 根据实际记录"。这类写给作者自己的话出现在正文里，说明生成时把提示词写进了文章，删掉。
B5. 断层检测：若某些段落零瑕疵、另一些段落密集出错，这是拼接稿。
    ⚠ 不要抹平。保留人工段落的口语、长句和毛边，把机械段改到同一水平——不是把人工段修成机器的样子。
B6. 中英混排：中文字符与英文、数字之间统一加半角空格，或统一不加，不能半篇加半篇不加。

■ C 内容

C1. hedging 每 1000 字超过 3 处 → 砍。改后的结论强度不得高于原文。
C2. 抽象表态换成具体动作。不写"这让我更明白 X 的重要性"，写当事人实际做了什么、看到什么、卡在哪一步。
C3. 全文对同一对象的判断前后打架（第二节说"AI 的建议可能是错的"，第三节说"AI 能查出人察觉不到的错误"）→ 取信息量更强的一边，修掉矛盾。
C4. 声明腔（"本文仅供……""不构成……""由作者负责"）改成第一人称的具体交代。

═══ 第三步 · 绝对不许动 ═══

格式：
- 不合并段落，不拆分段落。段落数必须和原文一模一样——合并会改变整篇的节奏设计，也会打乱自动编号。
- 不改段落样式、字体、字号、行距、缩进、对齐、项目符号。
- 不新增或删除标题、目录条目、页码、页眉页脚。

事实：
- 不添加原文没有的东西：不编数字、不编个人经历、不编课程名和题号、不编引用。
- 不改任何数字、单位、引用标记（如 [1][2]）、代码、公式、DOI、链接、文献著录格式。
- 不把"未检验"改成"失败"，不把"可能"改成"确定"，不删限定词和否定范围。
- 不加假错字、假口头禅、假意外来制造"人味"。

语言：
- 不把旧套话换成新套话："说白了""真正重要的是""值得注意的是""不得不说""这也让我意识到"一律禁止。
- 原文已有的有效口语、专业术语、长句、被动句，保留。

═══ 第四步 · 哪些段落必须跳过 ═══

遇到下列情况，不要改，写进 skipped 并说明原因：

- 含域代码的段落（目录条目、页码、表 1 / 图 1 这类交叉引用）。改了会破坏域，重开文档直接变成错误提示。
- 含图片、图表题注、脚注标记、批注的段落。
- 含超链接的段落（参考文献的 DOI 行就是）。
- 表格内的文字：默认不改。确有必要的，在 scope 里单独标出，由我手动确认。
- 页眉、页脚、封面信息栏：完全不碰。
- 段落内有多种字符格式混排（同一段里既有加粗又有正常字）：跳过，整段合并会抹掉段内的强调。

═══ 第五步 · anchor 规则 ═══

每处修改要用原文定位，脚本靠它找段落。

- anchor 取该段开头的 12–16 个字，必须在全文唯一。
- 不许用"首先""此外""综上所述"这类可能重复的开头。
- 段落中间的引用标记、数字、代码要包含在 anchor 里，让定位更准。
- scope 三选一：body（正文）/ table（表格内）/ header（页眉页脚，一般不用）。

═══ 第六步 · 输出格式 ═══

只输出一个 JSON 代码块，前后不要有任何说明文字。

{
  "edits": [
    {
      "anchor": "该段开头的前 12–16 字",
      "scope": "body",
      "note": "一句话说这处改了什么（不进文档，只给我看）",
      "new_text": "该段改后的完整正文"
    }
  ],
  "skipped": [
    { "anchor": "……", "reason": "contains_field / contains_hyperlink / mixed_format / table_locked" }
  ],
  "selfcheck": {
    "para_cv_before": 0.19,
    "para_cv_after": 0.33,
    "sent_cv_before": 0.34,
    "sent_cv_after": 0.47,
    "equal_length_runs_before": 2,
    "equal_length_runs_after": 0,
    "triple_parallelism_before": 11,
    "triple_parallelism_after": 4,
    "modal_words_before": 52,
    "modal_words_after": 21,
    "unsolved": ["仍然存在的 AI 痕迹，如实写 2–5 条"]
  }
}

new_text 要求：
- 必须是该段改完后的**完整文字**，不是片段、不是省略号。
- 保留原段的引号样式、全角标点、中英文空格习惯。
- 原段里的 [1][2] 引用标记，在新文本中按原位置保留。
- 长度可以与原文不同，但不能把两段的内容合成一段。

═══ 第七步 · 自检报告 ═══

自检数据只放在 JSON 的 selfcheck 字段里。
**不要把自检写进 new_text，不要写进文档正文，不要生成"修改说明"章节。** 文档里只应该有改好的文章，不该出现任何关于修改过程的话。

如果某处你没能解决，如实写进 unsolved。不要声称全部消除。

═══ 如果你拿到的只是纯文本 ═══

没有脚本可用时，仍然按上面的 JSON 输出。我会人工按 anchor 找到段落、整段选中、用"只保留文本"的方式粘贴。
这种情况下 anchor 要更严格：12–16 字，全文唯一，不要用标点开头的句子。

═══ 输入 ═══

文章如下：
"""
（在此粘贴正文，或上传 docx）
"""
```

## 落地

```bash
pip install python-docx

# 1. 先拍一张结构快照
python scripts/docx_fingerprint.py 论文.docx

# 2. 把 AI 返回的 JSON 存成 edits.json，先空跑
python scripts/apply_edits.py 论文.docx edits.json --dry-run

# 3. 正式应用
python scripts/apply_edits.py 论文.docx edits.json --out 论文-改.docx

# 4. 比对结构，必须输出"结构一致"
python scripts/docx_fingerprint.py 论文.docx 论文-改.docx
```

第 4 步不通过就不要交。它会把被改动的段落样式、段落属性、表格、图片、域、页眉页脚逐条列出来。

## 收尾两件事

1. **目录域**：正文长度变了，目录页码会失准。在 Word 里 `Ctrl+A` → `F9` → 只更新页码，或右键目录 → 更新域。脚本和 AI 都不碰目录。
2. **封面字段**：姓名、学号这类占位符要自己填，别让 AI 代填。

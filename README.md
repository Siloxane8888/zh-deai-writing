# zh-deai-writing ｜ 人迹

**降低中文写作里的 AI 痕迹，同时不动文档格式。**

给一份 `.docx` 论文或报告，AI 只回来一份"哪一段改成什么"的补丁清单，由脚本就地替换文字。标题样式、目录、自动编号、页眉页脚、表格、图片、引用标记，全部保持原样。

> 名字取"留人迹、去机痕"的意思。真正让文字像人写的，是作者自己留下的东西——卡过的点、改过的错、没想明白的地方——不是把句子改得更花。

**实测**：一段完全由 ChatGPT 生成的中文文字，腾讯朱雀检测为 *100% 疑似 AI 生成*；套用本提示词改写后，同一工具检测为 *100% 人工写作*。全过程没有加入任何个人经历、没有新增任何事实。详见[实测记录](#实测记录)。

两种用法，按需选：

- **要改 Word 文档** → 用[补丁模式](#快速开始)，脚本落地，格式不动。
- **只要文本**（聊天、Markdown、网页、公众号）→ 用[纯文本版提示词](#纯文本版提示词不用脚本)，粘提示词 + 粘文章，直接拿回改好的正文。

## 它解决的两个问题

### 一、改哪里

AI 味的主要载体不是词表，是**均匀度**——段落长度、句长、段落开头方式、并列结构，四项都过于整齐。刻意避开"维度""赋能""值得注意的是"之后，文本照样能被认出。

实测一篇 4200 字中文课程报告（28 个正文段）：

| | 机器生成的 23 段 | 人工插入的 5 段 |
|---|---|---|
| 段长均值 / 中位 | 151.4 / 147.0 | 119.0 / 99.0 |
| 段长变异系数 CV | **0.19** | **0.70** |
| 长度区间 | 106–222 | 33–270 |

均值和中位几乎重合，说明分布对称、没有长尾——批量生成的典型形状。同一篇里还找出四处连续 32 字的句子、三处连续 38 字的句子，人写不出来。

详见 [docs/why-uniformity.md](docs/why-uniformity.md)。

### 二、怎么改而不毁格式

`.docx` 不是文本文档，是压缩包里的关系图。正文 XML 里一个段落由 `pPr`（样式/缩进/间距/编号）+ 若干 `rPr`（字体/字号/加粗）+ `w:t`（文字）组成。AI 回传全文，等于把前两者全丢了。

所以这里的做法是**补丁模式**：AI 输出 `{anchor, new_text}`，脚本找到对应段落，保留 `pPr` 和第一个 run 的 `rPr`，只换文字。

详见 [docs/docx-safety.md](docs/docx-safety.md)。

## AI 痕迹从哪来

不是"AI 爱用某些词"这么简单。痕迹有六个机制来源，各自的修法不一样。

**1. 自回归解码走最平坦的路。**
模型每一步都在选概率最高的下一个 token。最高的那条路径就是最不冒险的那条：句子长度趋同、用词收敛、结构对称。人写作时会因为一时想不起某个词而绕开、会突然想到别的事而跑题，机器不会主动走偏。表现出来就是句长中位数稳定在 35 字上下、段长 CV 掉到 0.19。
→ 修法：在段和句两个层级上强行制造长度落差。

**2. "一个论点一段、每段三到五句"的模板。**
指令微调教会了模型这个结构，它在结构上没错——错在批量应用，于是每段差不多长。
→ 修法：把靠得近的两个短段并成一段长叙述，或把一个均匀段拆成一长一短。

**3. 三项并列是概率峰值。**
"德智体""知情意行""是什么、为什么、怎么办"——中文语料里三项结构出现频率最高。模型列举时默认凑三项。
→ 修法：超过每 500 字 1 处就拆成两项或改成一长句。

**4. 对齐训练留下了 hedging。**
RLHF 奖励"不越界、有分寸"的回答，于是每个结论后面自动挂一句免责："较稳妥的判断是""适合说明一种可能发生的过程""仍需通过具体任务观察"。人的学术写作也有限定，但不会这么密、这么规整。
→ 修法：每 1000 字超过 3 处就砍，改后结论强度不得高于原文。

**5. 分节生成会留下内部矛盾。**
长文往往是按章节分别生成的，每一节不知道上一节写了什么。结果：同一个分类在摘要、表格、正文里各有一套名字；题名里留着批量替换的残渣（把"Python 学习"换成"代码"，得到"代码学习学习"）；第二节说"AI 的建议可能是错的"，第三节说"AI 能查出人察觉不到的错误"。
→ 修法：跨节核对分类名称与顺序、题名四处一致性、全文立场一致性。这一类比句子问题更难被检测器发现，但人一读就发现。

**6. 训练语料里的学术套话，和一种格式洁癖。**
"随着……的发展""具有重要的理论意义"是真实存在过的论文用语，模型学到了它们的分布。同时模型输出的标点、空格、编号高度一致——人写的时候会漏空格、混全角半角。所以**零瑕疵本身就是信号**：如果一些段落毫无错漏、另一些段落密集出错，那不是写得好坏的问题，是两个来源拼在一起。
→ 修法：不要抹平。把机械段改到有毛边的水平，而不是把人工段修成机器的样子。

## 实测记录

一段完全由 ChatGPT 生成的中文文字，未做任何人工改动，直接送检：

| 阶段 | 腾讯朱雀检测结果 |
|---|---|
| 原文 | 100% 疑似 AI 生成 |
| 套用 [prompt/zh-deai.prompt.md](prompt/zh-deai.prompt.md) 改写后 | 100% 人工写作 |

改写过程只做了提示词里列出的动作：打散段长与句长、拆掉三项排比、删掉 hedging、把抽象表态换成具体动作。没有加入任何个人经历，没有新增任何事实。

**三点边界，请一起看：**

- **单样本。** 一次结果不构成通用保证。换文本、换字数、换文体，结果都可能不同。
- **工具特定。** 不同检测器的判据互不相同，朱雀通过不等于其他工具通过。
- **检测器不是标准。** 它给出的百分比不是概率，也不能证明作者身份。把它当作"某一类读者的第一印象"来参考，不要当判决。

## 快速开始

```bash
pip install python-docx
```

**1. 拍结构快照**（改之前）

```bash
python scripts/docx_fingerprint.py 论文.docx
```

会打印段落数、样式分布、表格、图片、域代码、页眉页脚，以及**段内格式混排的段落**——这些段落不能整段改写，先看清楚。

**2. 用提示词**

复制 [prompt/zh-deai.prompt.md](prompt/zh-deai.prompt.md) 里代码块的内容，末尾粘上正文或上传 docx。AI 会回一个 JSON。

存成 `edits.json`。

**3. 空跑**

```bash
python scripts/apply_edits.py 论文.docx edits.json --dry-run
```

检查 `applied` / `skipped` / `ambiguous` / `not_found`。有 ambiguous（anchor 不唯一）就让它写长一点；有 not_found 就是 anchor 没对上。

**4. 应用**

```bash
python scripts/apply_edits.py 论文.docx edits.json --out 论文-改.docx
```

**5. 验结构**

```bash
python scripts/docx_fingerprint.py 论文.docx 论文-改.docx
```

必须输出「结构一致」。不通过就别交。

**6. 收尾**

Word 里 `Ctrl+A` → `F9` 更新目录页码。封面的姓名学号自己填。

## 纯文本版提示词（不用脚本）

只要文本、不涉及 Word 的场合用这个：**提示词 + 文章**，直接拿回来的就是改好的正文。

输出里不含自检数据、不含修改说明——避免它被顺手粘进文档。想要指标就直接问它要，别让它默认给。

复制下面整段，末尾接你的文章：

```
你是中文写作编辑。下面是我的文章，请改写以降低 AI 痕迹。

【输出】只给改好的正文。不要前言、不要总结、不要"以下是改写后的版本"、不要自检数据、不要修改说明。我拿到就直接用。

【核心判断】AI 痕迹的主要载体不是词汇，是均匀度：段落长度、句长、段落开头方式、并列结构，四项都过于整齐。刻意避开"维度""赋能""值得注意的是"之后，文本照样能被认出。

【节奏】
1. 段落长度变异系数 CV = 标准差 ÷ 均值，低于 0.25 就打散，改到 0.30–0.40。最长段与最短段字数比 ≥ 4。至少留 2 个 50 字以内的独立短段。
2. 句长 CV 目标 ≥ 0.45。全文必须同时存在 10 字以内短句和 60 字以上长句。
3. 同段内连续 3 句字数完全相同，一律拆改；连续 2 句相同要复核。
4. 每段都用"话题句 + 判断句"起笔的，改掉约三分之一，换成从具体动作、具体数字或具体卡点起笔。
5. "可以 / 如果 / 若 / 先 / 再 / 最后 / 首先 / 其次 / 需要 / 适合 / 通常"超过每 50 字 1 次，砍一半。不要用同义词轮换降频（"可以"换"能够"），要删句、换句型、改主语。

【结构】
6. 三项并列排比超过每 500 字 1 处就拆成两项，或改成一长一短。
7. 同一分类在摘要、表格、正文出现多次时，核对三处名称与顺序是否一致，不一致就统一成一套。
8. 搜"需由作者 / 待补 / 此处 / 本稿 / 根据实际记录"。这类写给作者自己的话出现在正文里，说明生成时把提示词写进了文章，删掉。
9. 若某些段落零瑕疵、另一些段落密集出错，这是拼接稿。不要抹平——保留人工段落的口语和长句，把机械段改到同一水平，而不是把人工段修成机器的样子。

【内容】
10. hedging 短语（"较稳妥的判断是""适合说明一种可能发生的过程""仍需通过具体任务观察""只对应当次任务"）每 1000 字超过 3 处就砍。改后的结论强度不得高于原文。
11. 抽象表态换成具体动作。不写"这让我更明白 X 的重要性"，写当事人实际做了什么、看到什么、卡在哪一步。
12. 全文对同一对象的判断前后打架的，取信息量更强的一边，修掉矛盾。
13. 声明腔（"本文仅供……""不构成……""由作者负责"）改成第一人称的具体交代。

【不许动】
- 不添加原文没有的事实：不编数字、不编个人经历、不编课程名和题号、不编引用。
- 不改任何数字、单位、引用标记（如 [1][2]）、代码、公式、链接、文献著录格式。
- 不把"未检验"改成"失败"，不把"可能"改成"确定"，不删限定词和否定范围。
- 不加假错字、假口头禅、假意外来制造"人味"。
- 不用"说白了""真正重要的是""值得注意的是""不得不说"这类新套话。
- 保留原有的章节标题、编号层级和段落归属。

【段落规则】默认允许合并相邻短段、拆分长段。如果我会把结果粘回 Word 并需要保留原有段落结构，我会在文末写"保持段落数"，此时不要合并或拆分段落。

文章如下：
```

**两点提醒**

- 如果结果要粘回 Word，务必让它"保持段落数"，否则合并段落会打乱自动编号和目录。
- 想核对它有没有真做到，直接追问一句"报一下改前改后的段长 CV、句长 CV、连续等长句数量"。它会在对话里给，不会混进正文。

## 脚本会主动拒绝的情况

`apply_edits.py` 只在完全安全时才改。以下一律跳过并在报告里说明：

| 段落含 | 原因 |
|---|---|
| 域代码（`fldChar` / `instrText`） | 目录、页码、表图交叉引用会断 |
| 图片 / 脚注 / 批注 | 重建 run 会丢锚点 |
| 超链接 | 链接文字不在 `p.runs` 里，硬改会重复 |
| 手打换行 / 制表位 | 会被压平 |
| 段内有加粗、斜体等混排 | 整段合并会抹掉段内强调 |
| anchor 命中多个段落 | 定位不唯一，宁可不动 |

表格内文字默认锁定，要改得显式加 `--allow-table`。

## 适用范围

- 用于**自己写的**中文稿子：论文、课程报告、技术文档、工作汇报。
- 提示词里有一条硬约束：不编造原文没有的数字、经历、课程名和引用。降低痕迹的正确方向是**把作者放回去**，不是给机器文本加装饰。
- 元数据（累计编辑时长、修订次数）和真实记录（哪道题、什么报错）管不了。这两样只能靠真的动手。
- 保留并写准 AI 使用声明。读者判断"是不是 AI 写的"，看的是作者有没有自己的东西，不是有没有用过工具。
